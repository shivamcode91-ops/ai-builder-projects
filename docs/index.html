How the demos are built

Every one of these is a static page on GitHub Pages. There is no server in the path — which is the point, not a limitation: it is what lets a stranger paste an API key into a page a stranger wrote.

Demo first, always

Nothing asks you for anything to see the product work. AgentGuard's rule engine runs live and its model layer serves a labelled recording; the workbench serves real pipeline output; Vitalis ships sample readings. Recorded content says so on screen, every time.

Your key never reaches me

When you supply a key it goes from your tab straight to the provider. It lives in sessionStorage and dies with the tab — never localStorage, never a cookie, never a URL, and never a server of mine, because there isn't one.

The failures are on the page too

AgentGuard scores 9/10 and explains the tenth rather than hiding it. The workbench declines one of its three companies. A demo that only shows the happy path is a slideshow.
